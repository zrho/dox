- Product and scope
  - Build `dox`, a Zettelkasten-like notes app.
  - MVP: create, edit, and browse linked notes with tags and backlinks.
  - Initially single-user and local, with macOS as the priority platform.
  - Support one library initially; leave room for multiple libraries later.
  - Support lightweight Git history and moving libraries between computers through a changes pane; leave repository setup and advanced Git work external.
  - Advanced reference management and AI features are outside the MVP; single-entry BibTeX literature items are supported.

- Architecture
  - Rust native backend, with shared functionality in the `dox-core` library crate.
  - Embed the Typst compiler through `typst-as-lib`, with HTML export, standard fonts, local imports, and Typst Universe packages. Compile in process rather than launching an external executable. Keep compilation and package downloads off the desktop UI and async runtime threads.
  - `dox-cli` exposes core functionality through a CLI.
  - `dox-gui` provides a Tauri app with a TypeScript and SolidJS frontend.
  - Future AI functionality lives in `dox-core` and is exposed through both CLI and GUI; behavior will be specified later.

- Library and storage
  - Store notes in the filesystem under the library’s `notes/` directory, with one directory per note. Keep `.git`, `.cache`, and `.trash` at the library root.
  - Each note has a randomly generated ID matching `[0-9A-Z]{5}`, unique within its library.
  - Each note contains one source document and a `meta.json` referencing that document.
  - Required metadata: note type and source document reference.
  - Support optional metadata such as title, authors, date, and tags.
  - New Typst notes store the current local calendar date in source with `#metadata("YYYY-MM-DD") <dox-date>`. Literature dates come from BibTeX `date` or `year` with optional `month`/`day`. Preserve partial dates, allow dates to be absent, and show the ID and known date in a compact footer beneath each column’s backlinks in both edit and view modes; no date picker.
  - Support deriving metadata from document content, merging it with explicit metadata, and caching the merged result.
  - Titles support Typst syntax, including math. Cache compiled title HTML for display throughout the UI, retaining Typst source for link labels and plain text for search.
  - Store generated files and caches outside version control; a Git-ignored `.cache` directory within the library is acceptable.
  - Show the cached index promptly on startup and refresh it in the background without blocking note interaction.
  - Reuse per-note compilation caches based on source/metadata revisions and compiler-reported dependencies; revalidate link diagnostics without recompiling unrelated notes.
  - Watch library files for external changes and update the app accordingly.
  - Deleting a note moves its directory into a Git-ignored `.trash` directory within the library. Support Undo and CLI restoration; check the note revision before deletion.
  - Leave room for future note types, multiple libraries, and cross-library references qualified by a library ID.

- Note content and connections
  - Support file attachments for all item types. Copy files into each item's `attachments/` directory, preserve filenames with collision suffixes, and show a collapsible panel beneath backlinks. Open attachments in the system's default app and confirm removal of the library's copy; keep unsaved source edits intact. Include attachments when deleting/restoring an item and refresh externally changed files.
    - Accept native file drops onto the pane under the pointer, in edit and view modes, with a visible drop destination. Use the existing attachment import path, preserve drafts, and ignore drops outside panes or during other operations.
  - Typst is the default writing format, compiled to HTML for viewing.
  - Render equations as SVG through Typst `html.frame` in both documents and titles, preserving inline/display layout and avoiding nested conversion inside existing diagram frames.
  - Prioritize working math and diagram support, including packages such as CeTZ and Fletcher.
  - HTML output need not reproduce PDF layout exactly.
  - Render sanitized note HTML directly in the app with Shadow DOM style isolation; do not use iframes. Preserve MathML/SVG output and route note links through app navigation.
  - Support links between notes, tags, and backlinks.
  - Clicking note links, citations, or backlinks focuses and reveals an existing pane or appends a new one, preserving all open panes and unsaved drafts.
  - Initially express note links as ordinary links in Typst; frontend JavaScript turns them into in-app navigation actions.
  - Literature items have type `literature` and contain one bibliographic reference per note, backed by a BibTeX file instead of a Typst file.
    - Use the `biblatex` crate for parsing and typed field interpretation. Support comments, string definitions, concatenation, and name parsing while enforcing one bibliographic entry per item and its generated ID as the citation key. Preserve imported source when replacing keys via parser spans; serialize resolved entries for the shared citation bibliography to isolate per-item macros.
    - Automatically attach the PDF for arXiv imports, preserving the reference with a warning if the download fails. Provide a Find and attach paper PDF command for the focused literature item, using its current BibTeX draft without saving it. Resolve explicit arXiv identifiers or conservatively match arXiv title/author/DOI metadata; reject ambiguous matches, incomplete downloads, and non-PDF responses. Reuse identical attached PDFs. Keep PDF source resolution separate from general attachment storage for future providers.
    - Provide an Import publication from link or tag command with a text-entry dialog. Resolve DOI strings/links and current/legacy arXiv IDs/links in the core, retrieve online metadata, and create a validated single-entry BibTeX item only on success. Keep errors in the dialog and preserve open drafts.
    - Use the note's generated ID as its citation key.
    - Citations from Typst notes support navigation and backlinks similarly to ordinary note links. Generate the library bibliography in the disposable cache, but hide its rendered list. Show target titles in component tooltips on citations and note links.

- Editing and UI
  - Use Lucide icons, including a type icon for each item.
  - Show the open library path in the status bar, truncating the path while keeping the full value in a tooltip. Show a compact clickable Git status item beside the path for branch, changed files, and ahead/behind counts; open libraries through the command panel, and omit a dedicated tags panel for now.
  - Use Command-P to open a compact fuzzy note picker with title/ID matching, arrow-key selection, Enter to focus and reveal an existing pane or append a new one, preserving existing panes and drafts, and Escape to dismiss.
  - Provide a New empty literature item command, showing literature in pickers with a book icon.
  - Command-Shift-P opens a fuzzy command panel with keyboard navigation and displayed keybindings. Define commands and their keybindings centrally.
  - Create notes immediately without a dialog; focus the editor with a replaceable heading, and derive the title from the content.
  - Keep empty states quiet and omit onboarding copy.
  - Support editing both inside dox and in external editors.
  - Render the note title as a small heading at the top of the scrolling body instead of in the pane chrome. Use the system sans-serif font throughout, including note bodies, and fade the note scrollbar out once scrolling stops.
  - Render a literature item's `url` field as a link that opens in the system browser, and open other web links in rendered notes the same way.
  - Allow dragging panes by the narrow strip beneath their top edge to reorder them with CSS transitions, edge scrolling, and Escape cancellation. Preserve mounted editors, drafts, and scroll state; respect reduced-motion preferences.
  - GUI switches between editing and viewing modes with E or Escape, or one icon button (pencil to edit, eye to view); live preview is not required. Use D outside text fields to delete the focused note after confirmation, with an undo command for the last deletion.
  - Escape dismisses transient error/warning messages first, then exits editing through the same save/view action as E; retain contextual dialog and viewed-pane dismissal. Ignore held Escape repeats. Use j/Left and k/Right to focus and reveal adjacent open panes in visual order without wrapping, leaving text fields and their caret movement alone. Use Shift-J/Shift-Left and Shift-K/Shift-Right to swap the focused pane with its neighbour. Define and display both shortcut alternatives in the central command registry.
  - Command-K while focusing the editor opens a fuzzy note picker and inserts a Typst link at the selection, then returns focus to the editor. Selecting a literature item inserts `@ID` instead. Command-Shift-K uses the same picker and includes the publication title before its citation, escaping Typst characters in bibliographic titles.
  - Use compact toolbar and content padding; show backlinks without a separate outgoing-links panel.
  - Backlinks and diagnostics share a compact, collapsible note-info panel with subtle uppercase headings. Hide the backlinks panel when there are no backlinks.
  - Use Kobalte headless components, Tailwind CSS, and reusable design-system components in `src/ui/components/`, including shared fuzzy-picker behavior, buttons, inputs, and info panels.
  - Take visual inspiration from Zed: clean lines, compact and functional controls, content-first presentation, and unobtrusive UI.

- Diagnostics
  - Provide structured diagnostics in `dox-core`, exposed through the CLI and GUI.
  - Levels: error, warning, proposal. Proposals will describe future AI suggestions; do not generate or execute AI actions yet.
  - Compilation failures, malformed/unreadable notes, and dangling note links are errors.
  - Capture compiler warnings; invalid metadata dates and unsupported note types are warnings.
  - Include stable IDs, diagnostic codes, messages, originating note/document, optional source coordinates, related note targets, and optional suggested-action data.
  - Show a compact library diagnostics panel with severity filters, expandable details, and navigation to the originating note/source position. Diagnostics refer to saved files.

- Lightweight Git integration
  - Require an existing regular repository rooted at the library, with identity, remote upstream, and authentication configured externally. Use system Git on worker threads.
  - Show one reorderable Library changes workspace pane per window, grouping files by note and expanding bounded read-only text diffs inline. Show binary attachment filenames and sizes.
  - Commit all saved nonignored changes with an optional message, locally or followed by push. Require saving drafts in every associated window; offer Save all drafts for the current window. Keep hooks and signing active, preserve staging after failure, and refuse staging created externally.
  - Automatically check the remote on opening, app focus with a cooldown, and every five active minutes. Keep commit, pull, and push explicit. Pull only with a clean working tree and fast-forward history; never automatically stash or resolve divergence.
  - Share Git state and serialize operations per canonical repository path. Coordinate commit/pull with all windows and existing library writes; refresh notes after pulling. Keep offline work available and distinguish local commit success from push failure.
  - Exclude cloning, repository setup, branch management, staging controls, conflict resolution, history rewriting, and note history. Preserve .cache/.trash ignore rules and require externally untracking previously committed generated files.
